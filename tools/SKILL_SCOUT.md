# Разведчик открытых навыков Brain (#73)

`skill_scout.py` раз в неделю составляет **очередь кандидатов**, а не список
одобренных навыков. Он читает только публичные метаданные GitHub из
[`anthropics/skills`](https://github.com/anthropics/skills),
[`openai/skills`](https://github.com/openai/skills) (`skills/.curated`),
[`openclaw/agent-skills`](https://github.com/openclaw/agent-skills) и
[`NousResearch/hermes-agent`](https://github.com/NousResearch/hermes-agent).
Названия задач для сопоставления общие: сайты, магазины, деньги и налоги,
агенты, память и документы, безопасность. Частные данные владельца не входят
в запросы. Публичный `SKILL.md` читается только для `name` и `description` из
frontmatter; тело инструкции не попадает в отчёт.

Каждая карточка содержит задачу, точный commit и путь, ссылку на оригинал,
дату последнего обновления репозитория, статус лицензии, признак соседнего
каталога `scripts/`, `test=not_run` и
`state=candidate_unreviewed`. Наличие лицензии репозитория **не** доказывает
лицензию конкретного навыка. При отдельном файле LICENSE рядом с навыком
стоит `needs_per_skill_review`; иначе указан SPDX репозитория с пометкой
`repository_only`. Никакой навык не копируется, не устанавливается, не
исполняется и не включается в Brain автоматически. Ошибки API и обрезанное
дерево возвращаются в `errors`, а weekly job становится красным: это не
«навыков нет».

## Работа и проверки

```sh
python3 tools/skill_scout.py --per-source 2 > /tmp/skill-candidates.json
python3 tools/skill_scout.py --format markdown --from-json /tmp/skill-candidates.json
python3 -m unittest discover -s tools -p 'test_skill_scout.py'
```

Workflow `skill-scout.yml` запускает офлайн-тесты на PR, публичный просмотр
по понедельникам в 07:17 UTC и по ручному `workflow_dispatch`. JSON остаётся
артефактом Actions; краткая таблица — в summary запуска. Токен Actions имеет
только `contents: read`, передаётся API как заголовок и не печатается. Модель,
мост и данные владельца не вызываются. Публичный GitHub API может быть
недоступен или исчерпать rate limit: такой запуск не выдаётся за успешный.

## Перед включением кандидата

1. Проверить исходный `SKILL.md`, все упомянутые scripts и точную лицензию
   навыка и зависимостей; сравнить с уже установленными навыками Brain.
2. Проверить на синтетической задаче владельца в изоляции и добавить
   регрессионный тест. Установка ≠ полезное применение.
3. Включать в проект/агента отдельной проверяемой поставкой с допуском,
   квитанцией и возможностью отката. Этот разведчик не даёт разрешений.

Существующий локальный `ecc:skill-scout` помогает разовому поиску, а Brain
уже имеет read-only `/skills/` для одобренных навыков. Готовые системы вроде
[Hermes Skills Hub](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)
включают установку и изменение навыков; целиком второй runtime здесь не нужен.
Использован открытый формат `SKILL.md`, сторонний код не копировался. MCP
Registry содержит **инструменты**, а не `SKILL.md`; его разведка относится к
подключениям #60. LangGraph templates и awesome-списки могут стать следующими
источниками после отдельной проверки их форматов и лицензий.

Связка «повторился урок → кандидат навыка → тест → подтверждение» остаётся
частью #73 после конвейера памяти К4 (#61). Отчёт разведчика пока доступен в
Actions, а не в окне Brain Desk; для окна потребуется read-only проекция Brain.
